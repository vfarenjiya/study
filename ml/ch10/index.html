10. Bias-Variance Trade-off & Cross-Validation

Chapter 10 of 14 30 min read

The central question of model selection

Throughout this book, we have encountered a recurring tension. In Chapter 3, ridge regression shrinks coefficients to reduce variance at the cost of introducing bias. In Chapter 5, increasing \(k\) in kNN smooths predictions (lower variance) but loses local detail (higher bias). In Chapter 9, deeper decision trees fit training data perfectly but generalize poorly, while shallow trees underfit. Every hyperparameter choice across every algorithm reflects the same underlying tradeoff.

The question this chapter answers is: can we decompose prediction error into interpretable components that explain why models fail, and can we estimate generalization error without access to future data?

The answers are the bias-variance decomposition and cross-validation, respectively. Together, they form the theoretical and practical foundation for model evaluation and selection.

Setting up the decomposition

Consider a regression problem where the true data-generating process is:

\[y = f(x) + \varepsilon\]

where \(f(x)\) is the unknown true function and \(\varepsilon\) is irreducible noise with \(\mathbb{E}[\varepsilon] = 0\) and \(\text{Var}(\varepsilon) = \sigma^2\). We observe a training set \(\mathcal{D}\) drawn from this process and fit a model \(\hat{f}_{\mathcal{D}}(x)\), producing predictions that depend on which particular dataset we happened to observe.

We want to understand the expected prediction error at a fixed test point \(x_0\), averaged over both the noise in \(y\) and the randomness in the training set \(\mathcal{D}\):

\[\text{EPE}(x_0) = \mathbb{E}_{\mathcal{D}, \varepsilon}\left[(y_0 - \hat{f}_{\mathcal{D}}(x_0))^2\right]\]

where \(y_0 = f(x_0) + \varepsilon_0\) is a new observation at \(x_0\). This expectation captures what we actually care about: how well our procedure performs on average when applied to fresh data drawn from the same process.

Deriving the bias-variance decomposition

Define the average prediction at \(x_0\) across all possible training sets:

\[\bar{f}(x_0) = \mathbb{E}_{\mathcal{D}}[\hat{f}_{\mathcal{D}}(x_0)]\]

This is the prediction we would get if we could average over infinitely many training sets. Now add and subtract \(\bar{f}(x_0)\) inside the squared error:

\[(y_0 - \hat{f}_{\mathcal{D}}(x_0))^2 = \big((y_0 - f(x_0)) + (f(x_0) - \bar{f}(x_0)) + (\bar{f}(x_0) - \hat{f}_{\mathcal{D}}(x_0))\big)^2\]

Let \(A = y_0 - f(x_0) = \varepsilon_0\), \(B = f(x_0) - \bar{f}(x_0)\), and \(C = \bar{f}(x_0) - \hat{f}_{\mathcal{D}}(x_0)\). Then:

\[(A + B + C)^2 = A^2 + B^2 + C^2 + 2AB + 2AC + 2BC\]

Taking expectations over both \(\mathcal{D}\) and \(\varepsilon\):

  • \(\mathbb{E}[A^2] = \mathbb{E}[\varepsilon_0^2] = \sigma^2\) (irreducible noise)
  • \(\mathbb{E}[B^2] = (f(x_0) - \bar{f}(x_0))^2\) (constant w.r.t. both expectations)
  • \(\mathbb{E}[C^2] = \mathbb{E}_{\mathcal{D}}[(\hat{f}_{\mathcal{D}}(x_0) - \bar{f}(x_0))^2] = \text{Var}_{\mathcal{D}}(\hat{f}_{\mathcal{D}}(x_0))\)
  • \(\mathbb{E}[2AB] = 2\mathbb{E}[\varepsilon_0](f(x_0) - \bar{f}(x_0)) = 0\) (since \(\mathbb{E}[\varepsilon_0] = 0\))
  • \(\mathbb{E}[2AC] = 2\mathbb{E}[\varepsilon_0]\mathbb{E}_{\mathcal{D}}[\bar{f}(x_0) - \hat{f}_{\mathcal{D}}(x_0)] = 0\) (noise independent of training set; inner expectation is zero by definition of \(\bar{f}\))
  • \(\mathbb{E}[2BC] = 2(f(x_0) - \bar{f}(x_0))\mathbb{E}_{\mathcal{D}}[\bar{f}(x_0) - \hat{f}_{\mathcal{D}}(x_0)] = 0\) (inner expectation is zero)

All cross terms vanish. The result is the bias-variance decomposition:

\[\boxed{\text{EPE}(x_0) = \underbrace{(f(x_0) - \bar{f}(x_0))^2}_{\text{Bias}^2} + \underbrace{\text{Var}_{\mathcal{D}}(\hat{f}_{\mathcal{D}}(x_0))}_{\text{Variance}} + \underbrace{\sigma^2}_{\text{Irreducible Error}}}Three components, each with a clear interpretation:

Bias² measures how far the average prediction \(\bar{f}(x_0)\) is from the truth \(f(x_0)\). High bias means the model class is systematically wrong — it cannot represent the true function even with infinite data. Simple models (linear regression on nonlinear data, shallow trees) have high bias.

Variance measures how much \(\hat{f}_{\mathcal{D}}(x_0)\) fluctuates across different training sets. High variance means the model is overly sensitive to the particular sample observed. Complex models (high-degree polynomials, deep trees, 1-NN) have high variance.

Irreducible error \(\sigma^2\) is the noise floor. No model, regardless of complexity, can reduce error below this level. It represents genuine stochasticity in the data-generating process.

The tradeoff in action

As model complexity increases, bias typically decreases (the model can better approximate \(f\)) while variance increases (the model fits noise in the training set). The optimal complexity minimizes their sum. This is why:

  • Ridge regression's \(\lambda\) (Chapter 3): larger \(\lambda\) increases bias, decreases variance.
  • kNN's \(k\) (Chapter 5): larger \(k\) increases bias, decreases variance.
  • SVM's \(C\) (Chapter 8): larger \(C\) decreases bias, increases variance.
  • Decision tree depth (Chapter 9): deeper trees decrease bias, increase variance.
  • Laplace smoothing's \(\alpha\) (Chapter 6): larger \(\alpha\) increases bias, decreases variance.

Every hyperparameter in this book navigates this same tradeoff. Understanding the decomposition tells you why tuning matters, not just that it matters.

Worked example

Bias-variance decomposition for three estimators

Suppose the true function is \(f(x) = x^2\) and we observe noisy data \(y = x^2 + \varepsilon\) with \(\varepsilon \sim \mathcal{N}(0, 1)\), so \(\sigma^2 = 1\). We evaluate three estimators at \(x_0 = 2\) (true value: \(f(2) = 4\)) using repeated sampling from the training distribution \(x \sim \text{Uniform}[-3, 3]\), \(n = 20\).

We simulate conceptually (exact values illustrative):

Estimator A: Constant predictor \(\hat{f}(x) = 0\).

  • \(\bar{f}(2) = 0\) (always predicts 0)
  • Bias² = \((4 - 0)^2 = 16\)
  • Variance = 0 (prediction never changes)
  • EPE = \(16 + 0 + 1 = 17\)

Estimator B: Linear regression \(\hat{f}(x) = \hat{\beta}_0 + \hat{\beta}_1 x\).

  • Average fitted line approximates the best linear fit to \(x^2\) on \([-3,3]\), which is roughly \(\bar{f}(2) \approx 3.0\)
  • Bias² = \((4 - 3)^2 = 1.0\)
  • Variance ≈ 0.5 (moderate sensitivity to training samples)
  • EPE = \(1.0 + 0.5 + 1 = 2.5\)

Estimator C: Degree-10 polynomial regression.

  • Can fit \(x^2\) nearly perfectly on average: \(\bar{f}(2) \approx 4.0\)
  • Bias² ≈ 0
  • Variance ≈ 8.0 (extreme sensitivity: degree-10 polynomial oscillates wildly between training points)
  • EPE = \(0 + 8.0 + 1 = 9.0\)

Comparison:

Estimator Bias² Variance σ² EPE
Constant16.00.0117.0
Linear1.00.512.5
Degree-10 poly0.08.019.0

Linear regression wins despite having nonzero bias because its total EPE is lowest. The constant predictor has zero variance but catastrophic bias. The degree-10 polynomial has zero bias but catastrophic variance. The U-shaped EPE curve as a function of complexity is the visual manifestation of the bias-variance tradeoff.

Estimating generalization error: why holdout isn't enough

The bias-variance decomposition is theoretical — it requires knowing \(f(x)\) and averaging over infinitely many training sets. In practice, we have one dataset and need to estimate how well our model will perform on unseen data. The naive approach (training error) is optimistically biased because the model was optimized on that same data.

A single train/test split gives an unbiased estimate but with high variance: the estimate depends heavily on which points happened to land in the test set. With small datasets, this variability makes the estimate unreliable. We need methods that use data more efficiently.

Leave-One-Out Cross-Validation (LOO-CV)

LOO-CV uses \(n\) folds, each containing exactly one test point. For each \(i = 1, \ldots, n\):

  1. Train the model on all data except \((x_i, y_i)\).
  2. Predict \(\hat{y}_{-i}\) for the held-out point.
  3. Record the error \(e_i = (y_i - \hat{y}_{-i})^2\).

The LOO-CV estimate of test error is:

\[\text{LOO-CV} = \frac{1}{n}\sum_{i=1}^{n} e_i\]

LOO-CV is nearly unbiased for the true expected test error (each fold uses \(n-1\) training points, almost the full dataset). But it has two drawbacks: computational cost (\(n\) model fits) and potentially high variance when \(n\) is small (the \(n\) error estimates are highly correlated since each pair of folds shares \(n-2\) training points).

Worked example: LOO-CV for linear regression

Consider \(n = 4\) points: \((1, 2), (2, 4), (3, 5), (4, 4)\). We fit simple linear regression and compute LOO-CV MSE.

Fold 1: Hold out \((1, 2)\). Train on \(\{(2,4), (3,5), (4,4)\}\).

  • \(\bar{x} = 3, \bar{y} = 13/3\)
  • \(\hat{\beta}_1 = \frac{(2-3)(4-13/3) + (3-3)(5-13/3) + (4-3)(4-13/3)}{(2-3)^2 + 0 + (4-3)^2} = \frac{(-1)(-1/3) + 0 + (1)(-1/3)}{2} = \frac{1/3 - 1/3}{2} = 0\)
  • \(\hat{\beta}_0 = 13/3 - 0 \cdot 3 = 13/3 \approx 4.333\)
  • Prediction at \(x=1\): \(\hat{y}_{-1} = 4.333\)
  • Error: \((2 - 4.333)^2 = 5.444\)

Fold 2: Hold out \((2, 4)\). Train on \(\{(1,2), (3,5), (4,4)\}\).

  • \(\bar{x} = 8/3, \bar{y} = 11/3\)
  • Numerator: \((1-8/3)(2-11/3) + (3-8/3)(5-11/3) + (4-8/3)(4-11/3) = (-5/3)(-5/3) + (1/3)(4/3) + (4/3)(1/3) = 25/9 + 4/9 + 4/9 = 33/9\)
  • Denominator: \((1-8/3)^2 + (3-8/3)^2 + (4-8/3)^2 = 25/9 + 1/9 + 16/9 = 42/9\)
  • \(\hat{\beta}_1 = 33/42 = 11/14 \approx 0.786\)
  • \(\hat{\beta}_0 = 11/3 - (11/14)(8/3) = 11/3 - 88/42 = (154 - 88)/42 = 66/42 = 11/7 \approx 1.571\)
  • Prediction at \(x=2\): \(\hat{y}_{-2} = 11/7 + (11/14)(2) = 11/7 + 22/14 = 44/14 = 22/7 \approx 3.143\)
  • Error: \((4 - 22/7)^2 = (6/7)^2 = 36/49 \approx 0.735\)

Fold 3: Hold out \((3, 5)\). Train on \(\{(1,2), (2,4), (4,4)\}\).

  • \(\bar{x} = 7/3, \bar{y} = 10/3\)
  • Numerator: \((1-7/3)(2-10/3) + (2-7/3)(4-10/3) + (4-7/3)(4-10/3) = (-4/3)(-4/3) + (-1/3)(2/3) + (5/3)(2/3) = 16/9 - 2/9 + 10/9 = 24/9\)
  • Denominator: \(16/9 + 1/9 + 25/9 = 42/9\)
  • \(\hat{\beta}_1 = 24/42 = 4/7 \approx 0.571\)
  • \(\hat{\beta}_0 = 10/3 - (4/7)(7/3) = 10/3 - 4/3 = 6/3 = 2\)
  • Prediction at \(x=3\): \(\hat{y}_{-3} = 2 + (4/7)(3) = 2 + 12/7 = 26/7 \approx 3.714\)
  • Error: \((5 - 26/7)^2 = (9/7)^2 = 81/49 \approx 1.653\)

Fold 4: Hold out \((4, 4)\). Train on \(\{(1,2), (2,4), (3,5)\}\).

  • From Chapter 1 worked example: \(\hat{\beta}_1 = 1.5, \hat{\beta}_0 = 0.5\)
  • Prediction at \(x=4\): \(\hat{y}_{-4} = 0.5 + 1.5(4) = 6.5\)
  • Error: \((4 - 6.5)^2 = 6.25\)

LOO-CV MSE:

\[\text{LOO-CV} = \frac{1}{4}(5.444 + 0.735 + 1.653 + 6.25) = \frac{14.082}{4} = 3.521\]

This is our estimate of the expected test MSE for simple linear regression on this data-generating process.

k-Fold Cross-Validation

k-fold CV partitions the data into \(k\) roughly equal folds. For each fold \(j = 1, \ldots, k\):

  1. Train on all data except fold \(j\).
  2. Evaluate error on fold \(j\).

The k-fold CV estimate is the average error across all folds. Common choices are \(k = 5\) or \(k = 10\), balancing bias (each fold uses \((k-1)/k\) of the data) against variance (more folds means more correlated estimates) and computational cost (\(k\) fits instead of \(n\)).

k-fold CV is generally preferred over LOO-CV in practice because it is computationally cheaper and often has lower variance due to less correlation between fold errors. LOO-CV is preferred only when \(n\) is very small (say, \(n < 30\)) where wasting even \(1/k\) of the data per fold matters significantly.

Common mistake

Common mistake: Students sometimes perform feature selection, hyperparameter tuning, or preprocessing (e.g., standardization) on the full dataset before applying cross-validation. This leaks information from the test folds into the training process, producing optimistically biased error estimates. All data-dependent decisions must be made within each CV fold: standardize using only the training fold's statistics, select features using only the training fold, tune hyperparameters using nested CV. The test fold must remain completely untouched until the final evaluation step. Violating this principle is the single most common source of inflated performance claims in machine learning.

Edge case

What happens when \(k = n\) in k-fold CV? This is exactly LOO-CV. What happens when \(k = 1\)?

The entire dataset is both the training and test set, giving training error — maximally optimistic and useless for generalization estimation. Valid k-fold CV requires \(k \geq 2\). At \(k = 2\), each fold uses 50% of the data for training, introducing substantial pessimistic bias (the model is trained on half the available data). This is why \(k = 5\) or \(10\) is standard: sufficient training data per fold while maintaining reasonable computational cost and variance properties.

What about classification? The bias-variance decomposition as derived applies to squared-error loss in regression. For 0/1 classification loss, no exact additive decomposition exists, but the qualitative tradeoff persists: complex classifiers have low bias and high variance, simple classifiers have high bias and low variance. Cross-validation works identically for classification — simply replace squared error with misclassification rate (or log-loss) in each fold.

Where we go next

We now have the tools to evaluate and compare any supervised model rigorously. Chapter 11 shifts from classical methods to neural networks: multi-layer perceptrons and feed-forward architectures that learn hierarchical representations through backpropagation. Neural networks push the bias-variance tradeoff to its extreme — enormous capacity (near-zero bias) controlled by regularization and early stopping (variance management) — and the evaluation framework from this chapter applies directly to their training and tuning.
