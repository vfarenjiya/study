10. Decision Trees

Chapter 10 of 17 24 min read

Recursive partitioning and axis-aligned boundaries

Decision trees learn a hierarchy of simple decision rules that recursively partition the feature space into rectangular regions, each assigned a single prediction. For classification, each leaf stores a class label (typically the majority class of training points reaching it); for regression, each leaf stores a value (typically the mean response). The resulting decision boundary is axis-aligned: each split tests a single feature against a threshold (\(x_j \leq t\)), producing boundaries parallel to coordinate axes. This contrasts sharply with the oblique boundaries of logistic regression (Chapter 5), LDA (Chapter 8), and SVMs (Chapter 9).

The tree is built greedily via recursive binary splitting. At each node, the algorithm evaluates all possible splits across all features, selects the one that maximizes a chosen splitting criterion (measuring improvement in purity or reduction in error), partitions the data accordingly, and recurses on each child. Growth stops when a stopping condition is met: minimum node size, maximum depth, no improvement from any split, or pure node. This top-down induction is fast (\(O(np \log n)\) per level typically) and requires no feature scaling or distributional assumptions.

Common mistake: assuming decision trees are inherently interpretable because they produce human-readable rules. While shallow trees are interpretable, deep trees grown to minimize training error can have hundreds of nodes with complex interactions that defy comprehension. Interpretability is a property of regularized trees (via pruning or depth limits), not of the algorithm itself. Always report tree depth and number of leaves alongside accuracy; a 50-node tree achieving 85% accuracy may be less useful than a 5-node tree achieving 83%, depending on the application’s need for transparency versus performance.

Splitting criteria: Gini impurity and entropy

The splitting criterion quantifies how much a candidate split improves the homogeneity of class labels within child nodes relative to the parent. Two criteria dominate practice for classification:

Gini impurity

For a node containing samples with class proportions \(p_1, \dots, p_K\), Gini impurity is:

\[ G = \sum_{k=1}^{K} p_k (1 - p_k) = 1 - \sum_{k=1}^{K} p_k^2 \]

This equals the probability that two randomly drawn samples from the node have different classes. \(G = 0\) when the node is pure (all one class); \(G\) is maximized at \(1 - 1/K\) under uniform class distribution. The Gini gain of a split is the weighted decrease in impurity:

\[ \Delta G = G_{\text{parent}} - \left( \frac{n_L}{n} G_L + \frac{n_R}{n} G_R \right) \]

where \(n_L, n_R\) are child sample sizes and \(G_L, G_R\) their impurities. CART (the most common tree algorithm) uses Gini by default due to computational efficiency (no logarithms).

Entropy and information gain

Entropy measures uncertainty in bits (or nats):

\[ H = -\sum_{k=1}^{K} p_k \log_2 p_k \]

\(H = 0\) for pure nodes; \(H = \log_2 K\) for uniform distributions. Information gain is the entropy reduction:

\[ \Delta H = H_{\text{parent}} - \left( \frac{n_L}{n} H_L + \frac{n_R}{n} H_R \right) \]

ID3 and C4.5 use entropy/information gain. In practice, Gini and entropy yield nearly identical trees; differences arise mainly when class distributions are highly skewed or when splits produce very unbalanced children. Entropy penalizes unbalanced splits slightly more, which can be preferable when balanced subtrees aid interpretability.

Edge case: both criteria are biased toward features with many distinct values (especially continuous features with many candidate thresholds). A feature with unique values per sample can always achieve perfect purity by isolating each point, regardless of predictive relevance. C4.5 addresses this via gain ratio, normalizing information gain by the intrinsic information of the split itself. Modern implementations (e.g., scikit-learn) mitigate bias via minimum samples per leaf constraints rather than gain ratio. Always validate feature importance rankings against domain knowledge or permutation tests rather than trusting raw split frequencies.

Worked example: computing Gini and entropy gains

Parent node: 10 samples, 6 class A, 4 class B. \(p_A = 0.6, p_B = 0.4\).

\[ G_{\text{parent}} = 1 - (0.6^2 + 0.4^2) = 1 - (0.36 + 0.16) = 0.48 \] \[ H_{\text{parent}} = -(0.6 \log_2 0.6 + 0.4 \log_2 0.4) = -(0.6 \cdot (-0.737) + 0.4 \cdot (-1.322)) = 0.442 + 0.529 = 0.971 \text{ bits} \]

Candidate split produces left child (4A, 1B) and right child (2A, 3B). Left: \(p_A = 0.8, p_B = 0.2\); \(G_L = 1 - (0.64 + 0.04) = 0.32\); \(H_L = -(0.8 \log_2 0.8 + 0.2 \log_2 0.2) = 0.722\). Right: \(p_A = 0.4, p_B = 0.6\); \(G_R = 0.48\); \(H_R = 0.971\). Weighted averages:

\[ G_{\text{children}} = \frac{5}{10}(0.32) + \frac{5}{10}(0.48) = 0.16 + 0.24 = 0.40 \quad \Rightarrow \quad \Delta G = 0.48 - 0.40 = 0.08 \] \[ H_{\text{children}} = \frac{5}{10}(0.722) + \frac{5}{10}(0.971) = 0.361 + 0.486 = 0.847 \quad \Rightarrow \quad \Delta H = 0.971 - 0.847 = 0.124 \text{ bits} \]

Both criteria favor this split over alternatives with lower gains. Sensitivity check: if the split instead produced (5A,0B) and (1A,4B), left would be pure (\(G_L=0, H_L=0\)), right \(G_R=0.32, H_R=0.722\). Then \(\Delta G = 0.48 - [0.5(0)+0.5(0.32)] = 0.32\); \(\Delta H = 0.971 - [0+0.361] = 0.610\). Much larger gains reflect the near-perfect separation. Note that Gini and entropy rank splits identically here, but with three+ classes or extreme imbalance, rankings can diverge slightly.

Regression trees and variance reduction

For regression, splitting criteria measure reduction in response variability rather than class impurity. The standard criterion is mean squared error reduction:

\[ \Delta \text{MSE} = \text{MSE}_{\text{parent}} - \left( \frac{n_L}{n} \text{MSE}_L + \frac{n_R}{n} \text{MSE}_R \right) \]

where \(\text{MSE} = \frac{1}{n}\sum (y_i - \bar y)^2\) within each node. Equivalently, this maximizes the between-group sum of squares. Leaf predictions are the local mean \(\bar y\), making regression trees piecewise constant approximators. Unlike linear models (Chapters 2–4), trees capture nonlinearities and interactions automatically without explicit specification, but produce discontinuous predictions at split boundaries.

Edge case: MSE-based splits are sensitive to outliers, just like OLS. A single extreme \(y\)-value can dominate the variance reduction calculation and induce splits that isolate it, harming generalization. Robust alternatives include mean absolute error reduction or Huber loss, though these are less commonly implemented. Also note that regression trees cannot extrapolate beyond the range of training responses; predictions at test points outside the training feature bounds default to the nearest leaf’s mean, which may be wildly inaccurate. Always check feature ranges at prediction time.

Overfitting and pruning strategies

Unpruned trees grown until purity or minimum node size tend to overfit severely: they memorize noise and idiosyncrasies of the training set, producing deep, bushy structures with poor generalization. Training error decreases monotonically with tree size, but test error follows a U-shape — the classic bias-variance trade-off (Chapter 11). Three main strategies control complexity:

Pre-pruning (early stopping)

Halt growth based on heuristics: maximum depth, minimum samples per node/leaf, minimum impurity decrease per split. Simple and computationally cheap, but myopic: a split with negligible immediate gain might enable highly informative subsequent splits. Optimal thresholds require cross-validation (Chapter 12).

Post-pruning (cost-complexity pruning)

Grow a full tree, then prune back using cost-complexity:

\[ R_\alpha(T) = R(T) + \alpha |T| \]

where \(R(T)\) is training error (misclassification rate or MSE), \(|T|\) is number of leaves, and \(\alpha \geq 0\) penalizes complexity. For each \(\alpha\), find the subtree minimizing \(R_\alpha\) via weakest-link pruning (iteratively collapsing the internal node whose removal increases \(R\) least per leaf removed). Select \(\alpha\) by cross-validation. This is CART’s standard approach and generally outperforms pre-pruning because it considers global structure before simplifying.

Minimum description length and Bayesian approaches

MDL/Bayesian methods penalize tree complexity via encoding length or prior probabilities, offering principled alternatives to CV-tuned \(\alpha\). Less common in practice but theoretically elegant.

Common mistake: relying solely on training error or in-sample metrics to select tree size. Always use held-out validation or cross-validation. Also beware that pruned trees can still overfit if the validation set is small or non-representative; nested cross-validation provides more reliable estimates when data are limited.

Worked example: cost-complexity pruning path

Suppose a fully grown tree has 7 leaves with training misclassification rates summing to \(R(T) = 0.05\) (5 errors out of 100). Weakest-link pruning identifies collapse candidates with associated \(\alpha\) values where collapsing becomes optimal:

\[ \begin{array}{c|c|c} \text{Subtree} & |T| & R(T) \\ \hline T_0 \text{ (full)} & 7 & 0.05 \\ T_1 & 5 & 0.07 \\ T_2 & 3 & 0.10 \\ T_3 \text{ (root only)} & 1 & 0.20 \end{array} \]

Effective \(\alpha\) for each transition: \(\alpha_1 = (0.07 - 0.05)/(7 - 5) = 0.01\); \(\alpha_2 = (0.10 - 0.07)/(5 - 3) = 0.015\); \(\alpha_3 = (0.20 - 0.10)/(3 - 1) = 0.05\). For \(\alpha < 0.01\), keep full tree. For \(0.01 \leq \alpha < 0.015\), use \(T_1\). For \(0.015 \leq \alpha < 0.05\), use \(T_2\). For \(\alpha \geq 0.05\), use root-only. Cross-validation selects the \(\alpha\) (and corresponding subtree) with lowest validation error. Sensitivity check: if validation errors were [0.12, 0.09, 0.08, 0.18] for \(T_0,T_1,T_2,T_3\), then \(T_2\) wins despite higher training error than \(T_0\) — illustrating how pruning trades fit for generalization. If validation set were tiny and gave [0.06, 0.09, 0.11, 0.15], \(T_0\) would win spuriously; larger validation sets stabilize selection.

Feature importance and interaction detection

Decision trees naturally capture feature interactions: a split on \(x_j\) followed by a split on \(x_k\) in one branch but not another encodes a conditional dependency. This is impossible in additive models without explicit interaction terms. Feature importance is typically measured by total impurity decrease attributable to each feature across all splits where it was used, weighted by node sample sizes. Alternatively, permutation importance (shuffle feature values, measure accuracy drop) avoids biases toward high-cardinality features.

Edge case: correlated features share importance arbitrarily; if \(x_1\) and \(x_2\) are perfectly correlated, the tree picks one at random for each split, splitting importance roughly equally even if only one is causally relevant. Permutation importance also suffers: shuffling \(x_1\) leaves \(x_2\) intact, so accuracy drops little, understating true importance. Grouped permutation or conditional permutation addresses this. Also note that importance reflects predictive utility within the fitted tree, not causal effect; confounded features can appear important without being causally relevant.

Connection to the broader framework

Decision trees complement the linear and kernel-based methods of earlier chapters. Where logistic regression (Chapter 5) and SVMs (Chapter 9) produce smooth or margin-maximizing boundaries, trees produce piecewise-constant partitions adaptive to local structure. Where LDA (Chapter 8) assumes Gaussian class densities, trees are fully nonparametric. Where kNN (Chapter 6) stores all data, trees compress data into hierarchical rules. Chapter 11’s bias-variance decomposition explains why unpruned trees have low bias but high variance, and why pruning shifts this balance. Chapter 12’s cross-validation is essential for selecting pruning parameters and comparing trees to other models. And ensemble methods (not covered here but foreshadowed) — bagging, random forests, boosting — combine many weak trees to overcome individual instability while retaining flexibility, dominating tabular data competitions and practical applications.

Master decision trees not as standalone predictors (they rarely win alone) but as the building blocks of modern ensembles and as the clearest illustration of greedy hierarchical learning. If you can compute Gini/entropy gains by hand, trace a pruning path, diagnose overfitting from tree structure, and explain when axis-aligned boundaries help or hurt relative to linear separators, you have internalized the nonparametric, partition-based paradigm that complements the geometric and probabilistic views of earlier chapters.
