5. k-Nearest Neighbour

Chapter 5 of 14 20 min read

Learning without parameters

Every model we have studied so far — linear regression, ridge regression, logistic regression — is parametric: we assume a fixed functional form (linear, sigmoid) with a finite set of parameters \(\boldsymbol{\beta}\), and learning means finding the best parameter values. The model's complexity is determined before seeing any data.

But what if we don't know the right functional form? What if the true decision boundary is highly irregular, with twists and pockets that no linear or low-degree polynomial could capture? The question k-nearest neighbours answers is: can we build a classifier that adapts its complexity to the data itself, making no parametric assumptions whatsoever?

The answer is yes, and the idea is radically simple: to classify a new point, look at the training points closest to it and let them vote.

The algorithm

Given a training set \(\{(x_i, y_i)\}_{i=1}^n\) with \(y_i \in \{1, \ldots, C\}\) and a new test point \(x^*\), the k-nearest neighbour classifier proceeds in three steps:

  1. Compute distances: Calculate \(d(x^*, x_i)\) for every training point \(i = 1, \ldots, n\).
  2. Find neighbours: Identify the \(k\) training points with the smallest distances to \(x^*\). Call this set \(\mathcal{N}_k(x^*)\).
  3. Vote: Assign \(x^*\) the class that appears most frequently among the labels \(\{y_i : i \in \mathcal{N}_k(x^*)\}\).

That's it. There are no parameters to optimize, no gradient to compute, no likelihood to maximize. The entire "model" is the stored training set itself. kNN is sometimes called a lazy learner because all computation is deferred to prediction time.

Choosing a distance metric

The algorithm's behavior depends critically on how we measure "closeness." The most common choice is Euclidean distance:

\[d(x, x') = \|x - x'\|_2 = \sqrt{\sum_{j=1}^{p}(x_j - x'_j)^2}\]

But Euclidean distance treats all features equally. If feature 1 ranges from 0 to 1 and feature 2 ranges from 0 to 1000, feature 2 will dominate the distance calculation entirely, rendering feature 1 irrelevant. This leads to an essential preprocessing step: feature scaling. Standard practice is to standardize each feature to zero mean and unit variance before computing distances, so that each feature contributes equally to the notion of proximity.

Other metrics are sometimes appropriate: Manhattan distance (\(\ell_1\)) is more robust to outliers; cosine similarity measures angular rather than absolute proximity and is preferred for high-dimensional sparse data like text. But for the GATE DA syllabus, Euclidean distance on standardized features is the default assumption unless stated otherwise.

The role of \(k\): a bias-variance analysis

The single hyperparameter \(k\) controls the fundamental tradeoff in kNN. To understand why, consider the extremes.

When \(k = 1\): The prediction at \(x^*\) is simply the label of the single nearest training point. The decision boundary passes through the midpoints between every pair of differently-labeled neighbouring points, creating a highly complex, jagged boundary that can weave between individual data points. Training error is zero (every training point is its own nearest neighbour). But the prediction is extremely sensitive to noise: a single mislabeled point creates a pocket of wrong predictions around it. Variance is high; bias is low.

When \(k = n\): Every test point sees all training points as neighbours. The prediction is always the majority class in the entire training set, regardless of where \(x^*\) is located. The decision boundary disappears entirely. Variance is zero (the prediction never changes), but bias is maximal (the model ignores all local structure).

Intermediate \(k\): As \(k\) increases, the decision boundary smooths out. Local noise is averaged away (variance decreases), but fine-grained structure is lost (bias increases). The optimal \(k\) balances these forces, and it must be chosen by cross-validation (Chapter 10) — there is no theoretical formula that works universally.

A practical guideline: choose \(k\) to be odd when \(C = 2\) to avoid ties. More generally, \(k\) should grow with \(n\) but slower than \(n\) itself; theory suggests \(k \propto n^{4/(4+p)}\) under smoothness assumptions, though in practice cross-validation is the reliable method.

Worked example

Classifying a test point with \(k = 3\)

Suppose we have \(n = 6\) training points in \(\mathbb{R}^2\) with binary labels:

  • \(A = (1, 1)\), label = Red
  • \(B = (2, 3)\), label = Blue
  • \(C = (3, 2)\), label = Red
  • \(D = (4, 4)\), label = Blue
  • \(E = (5, 1)\), label = Red
  • \(F = (6, 3)\), label = Blue

Test point: \(x^* = (3, 3)\). We use \(k = 3\) and Euclidean distance.

Step 1: Compute distances from \(x^*\) to each training point.

We compute \(d(x^*, x_i) = \sqrt{(x^*_1 - x_{i1})^2 + (x^*_2 - x_{i2})^2}\) for each point:

  • \(d(x^*, A) = \sqrt{(3-1)^2 + (3-1)^2} = \sqrt{4 + 4} = \sqrt{8} \approx 2.828\)
  • \(d(x^*, B) = \sqrt{(3-2)^2 + (3-3)^2} = \sqrt{1 + 0} = \sqrt{1} = 1.000\)
  • \(d(x^*, C) = \sqrt{(3-3)^2 + (3-2)^2} = \sqrt{0 + 1} = \sqrt{1} = 1.000\)
  • \(d(x^*, D) = \sqrt{(3-4)^2 + (3-4)^2} = \sqrt{1 + 1} = \sqrt{2} \approx 1.414\)
  • \(d(x^*, E) = \sqrt{(3-5)^2 + (3-1)^2} = \sqrt{4 + 4} = \sqrt{8} \approx 2.828\)
  • \(d(x^*, F) = \sqrt{(3-6)^2 + (3-3)^2} = \sqrt{9 + 0} = \sqrt{9} = 3.000\)

Step 2: Sort by distance and select the 3 nearest.

Sorted distances:

  1. \(B\): 1.000 (Blue)
  2. \(C\): 1.000 (Red)
  3. \(D\): 1.414 (Blue)
  4. \(A\): 2.828 (Red)
  5. \(E\): 2.828 (Red)
  6. \(F\): 3.000 (Blue)

The 3 nearest neighbours are \(B\) (Blue), \(C\) (Red), and \(D\) (Blue).

Step 3: Majority vote.

Among \(\{B, C, D\}\): Blue appears 2 times, Red appears 1 time. The predicted class is Blue.

What if we used \(k = 5\)? The 5 nearest neighbours would be \(\{B, C, D, A, E\}\): Red appears 3 times, Blue appears 2 times. The prediction flips to Red. This demonstrates concretely how the choice of \(k\) affects the outcome and why cross-validation is necessary.

Tie-breaking: With \(k = 4\), the 4 nearest neighbours are \(\{B, C, D, A\}\): 2 Blue, 2 Red. This is a tie. Common resolution strategies include: (a) reduce \(k\) by 1 until the tie breaks; (b) choose randomly among tied classes; (c) weight votes by inverse distance so closer neighbours count more. Strategy (c) is often preferred because it uses information that unweighted voting discards. With inverse-distance weighting at \(k=4\): Blue weight = \(1/1.000 + 1/1.414 \approx 1.707\), Red weight = \(1/1.000 + 1/2.828 \approx 1.354\). Blue wins.

kNN for regression

kNN extends naturally to regression. Instead of majority voting, we average the target values of the \(k\) nearest neighbours:

\[\hat{y}(x^*) = \frac{1}{k} \sum_{i \in \mathcal{N}_k(x^*)} y_i\]

This is a locally constant estimator: within each region of feature space defined by a fixed set of \(k\) nearest neighbours, the prediction is constant. Weighted versions (inverse-distance weighting) produce smoother predictions. The same bias-variance tradeoff in \(k\) applies: small \(k\) gives low bias and high variance; large \(k\) gives high bias and low variance.

Computational cost and the curse of dimensionality

kNN has zero training cost (just store the data) but prediction cost of \(O(np)\) per test point: compute \(n\) distances in \(p\) dimensions. For large \(n\), this is prohibitive. Data structures like kd-trees and ball trees reduce average-case search to \(O(p \log n)\) in low dimensions, but their advantage vanishes as \(p\) grows.

This is the curse of dimensionality: in high-dimensional spaces, all points become approximately equidistant. The ratio of the nearest-neighbour distance to the farthest-neighbour distance approaches 1 as \(p \to \infty\), making the concept of "nearest" meaningless. kNN works well in low-to-moderate dimensions but degrades rapidly beyond \(p \approx 20\)–\(30\) without dimensionality reduction (Chapter 14).

Common mistake

Common mistake: Students often apply kNN without standardizing features, leading to predictions dominated by whichever feature has the largest numerical range. If age ranges from 20–80 and income ranges from 20,000–200,000, income differences will swamp age differences in the Euclidean distance, even if age is the more informative feature. Always standardize (zero mean, unit variance) or normalize (min-max to [0,1]) before computing distances. This is not optional preprocessing — it is part of the algorithm definition.

Edge case

What happens when multiple training points are exactly equidistant from \(x^*\) and fall on the boundary of the \(k\)-neighbourhood? For example, if the 3rd and 4th nearest neighbours have identical distances and \(k = 3\), which one is included? Different implementations break this tie differently (arbitrary ordering, random selection, including all tied points). This means kNN predictions can be non-deterministic across software packages. In exam settings, problems are typically constructed to avoid exact distance ties, but in practice, awareness of this ambiguity prevents debugging confusion.

Where we go next

kNN makes no assumptions about the data-generating distribution. But sometimes we want a probabilistic classifier that does make distributional assumptions — specifically, assumptions about how features are distributed within each class. Chapter 6 introduces the Naive Bayes classifier, which applies Bayes' theorem with a conditional independence assumption to produce fast, interpretable probabilistic predictions. Despite its "naive" assumption rarely being literally true, Naive Bayes performs remarkably well in practice and provides a complementary perspective to both the parametric models of Chapters 1–4 and the nonparametric approach of this chapter.
