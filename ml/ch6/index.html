6. Naive Bayes Classifier

Chapter 6 of 14 25 min read

Classifying by reversing causality

In logistic regression (Chapter 4), we modeled \(P(y|x)\) directly using a parametric sigmoid function. In k-nearest neighbours (Chapter 5), we avoided modeling probabilities altogether and classified by local voting. Both approaches sidestep a natural question: what if we already know (or can estimate) how features are generated within each class?

Consider spam detection. It is often easier to describe what spam emails look like — they contain words like "free," "winner," "click here," have many capital letters, suspicious links — than to directly model the boundary between spam and ham. We can naturally estimate \(P(\text{features} | \text{spam})\) and \(P(\text{features} | \text{ham})\) from labeled examples. But classification requires \(P(\text{spam} | \text{features})\), the reverse direction. Bayes' theorem bridges this gap.

Bayes' theorem for classification

For a feature vector \(x = (x_1, x_2, \ldots, x_p)\) and class label \(c \in \{1, \ldots, C\}\), Bayes' theorem gives:

\[P(y = c | x) = \frac{P(x | y = c) \, P(y = c)}{P(x)}\]

The three components have names: \(P(y=c)\) is the prior (how common is class \(c\) overall?), \(P(x|y=c)\) is the likelihood (how probable are these features under class \(c\)?), and \(P(x)\) is the evidence (a normalizing constant that ensures the posterior probabilities sum to 1 across classes).

For classification, we don't need the exact posterior probability — we only need to pick the class with the highest posterior. Since \(P(x)\) does not depend on \(c\), it cancels out in comparisons. The decision rule becomes:

\[\hat{y} = \arg\max_{c} P(x | y = c) \, P(y = c)\]

This is clean in principle but catastrophic in practice. The likelihood \(P(x | y = c)\) is a joint distribution over \(p\) features. Estimating a full joint distribution from finite data requires an exponential number of parameters: for \(p\) binary features, there are \(2^p\) possible feature combinations per class. With \(p = 30\), that's over a billion parameters per class — completely infeasible.

We need a simplifying assumption that makes the likelihood tractable. This is where "naive" enters.

The conditional independence assumption

Naive Bayes assumes that features are conditionally independent given the class:

\[P(x_1, x_2, \ldots, x_p | y = c) = \prod_{j=1}^{p} P(x_j | y = c)\]

This factorization reduces the number of parameters from exponential in \(p\) to linear in \(p\). For binary features and \(C\) classes, we need only \(C \times p\) conditional probabilities plus \(C\) priors, instead of \(C \times 2^p\).

Why call it "naive"? Because the assumption is almost never literally true. Words in emails are correlated ("free" and "winner" co-occur far more often than independence would predict). Medical symptoms cluster. Pixel values in images are spatially dependent. Yet Naive Bayes works surprisingly well in practice. Why?

Because classification only requires getting the ranking of posteriors correct, not their exact values. Even when the independence assumption distorts individual probability estimates, the distortions often affect all classes similarly, preserving which class has the highest posterior. The bias introduced by the assumption trades off against dramatically reduced variance from having far fewer parameters to estimate — another instance of the bias-variance tradeoff we will formalize in Chapter 10.

The Naive Bayes decision rule

Substituting the factorized likelihood into the MAP decision rule:

\[\boxed{\hat{y} = \arg\max_{c} \left[ P(y = c) \prod_{j=1}^{p} P(x_j | y = c) \right]}In practice, we work in log-space to avoid numerical underflow (multiplying many small probabilities produces numbers smaller than floating-point precision):

\[\hat{y} = \arg\max_{c} \left[ \log P(y = c) + \sum_{j=1}^{p} \log P(x_j | y = c) \right]\]

The log transform converts products to sums and preserves the argmax (since log is monotone increasing). This is the form used in all practical implementations.

Estimating the parameters from data

Given training data \(\{(x_i, y_i)\}_{i=1}^n\), the parameters are estimated by simple counting:

\[\hat{P}(y = c) = \frac{n_c}{n}\]

where \(n_c\) is the number of training examples with label \(c\). For categorical features, the conditional probabilities are:

\[\hat{P}(x_j = v | y = c) = \frac{n_{c,j,v}}{n_c}\]

where \(n_{c,j,v}\) is the number of training examples with class \(c\) and feature \(j\) equal to value \(v\). For continuous features, we typically assume a Gaussian distribution within each class and estimate the mean and variance per feature per class (Gaussian Naive Bayes), or discretize the feature first.

Worked example

Spam classification with three words

Suppose we have \(n = 8\) training emails, each described by the presence (1) or absence (0) of three words: "free," "money," "meeting." Labels: Spam (S) or Ham (H).

Step 1: Estimate priors.

\[\hat{P}(S) = \frac{4}{8} = 0.5, \quad \hat{P}(H) = \frac{4}{8} = 0.5\]

Step 2: Estimate conditional probabilities (without smoothing, for now).

For Spam (\(n_S = 4\)):

  • \(\hat{P}(\text{free}=1 | S) = \frac{3}{4} = 0.75\), \(\hat{P}(\text{free}=0 | S) = \frac{1}{4} = 0.25\)
  • \(\hat{P}(\text{money}=1 | S) = \frac{3}{4} = 0.75\), \(\hat{P}(\text{money}=0 | S) = \frac{1}{4} = 0.25\)
  • \(\hat{P}(\text{meeting}=1 | S) = \frac{0}{4} = 0\), \(\hat{P}(\text{meeting}=0 | S) = \frac{4}{4} = 1.0\)

For Ham (\(n_H = 4\)):

  • \(\hat{P}(\text{free}=1 | H) = \frac{0}{4} = 0\), \(\hat{P}(\text{free}=0 | H) = \frac{4}{4} = 1.0\)
  • \(\hat{P}(\text{money}=1 | H) = \frac{1}{4} = 0.25\), \(\hat{P}(\text{money}=0 | H) = \frac{3}{4} = 0.75\)
  • \(\hat{P}(\text{meeting}=1 | H) = \frac{3}{4} = 0.75\), \(\hat{P}(\text{meeting}=0 | H) = \frac{1}{4} = 0.25\)

Step 3: Classify a new email \(x^* = (\text{free}=1, \text{money}=0, \text{meeting}=1)\).

Compute unnormalized posteriors (ignoring \(P(x)\)):

\[P(S) \cdot P(\text{free}=1|S) \cdot P(\text{money}=0|S) \cdot P(\text{meeting}=1|S) = 0.5 \times 0.75 \times 0.25 \times 0 = 0\] \[P(H) \cdot P(\text{free}=1|H) \cdot P(\text{money}=0|H) \cdot P(\text{meeting}=1|H) = 0.5 \times 0 \times 0.75 \times 0.75 = 0\]

Both scores are zero! The word "free" never appeared in Ham, and "meeting" never appeared in Spam, so any test email containing both gets assigned zero probability under both classes. This is the zero-frequency problem, and it reveals a critical flaw in raw frequency estimation.

Laplace smoothing: fixing zero frequencies

The solution is Laplace smoothing (also called additive smoothing). Instead of estimating \(P(x_j = v | y = c) = n_{c,j,v} / n_c\), we add a pseudocount \(\alpha > 0\) to every count:

\[\hat{P}(x_j = v | y = c) = \frac{n_{c,j,v} + \alpha}{n_c + \alpha \cdot V_j}\]

where \(V_j\) is the number of possible values for feature \(j\). For binary features, \(V_j = 2\). Setting \(\alpha = 1\) gives Laplace smoothing; \(\alpha = 0.5\) gives Lidstone smoothing.

Recomputing with \(\alpha = 1\):

For Spam (\(n_S = 4, V = 2\)):

  • \(\hat{P}(\text{free}=1 | S) = \frac{3+1}{4+2} = \frac{4}{6} \approx 0.667\)
  • \(\hat{P}(\text{free}=0 | S) = \frac{1+1}{4+2} = \frac{2}{6} \approx 0.333\)
  • \(\hat{P}(\text{money}=1 | S) = \frac{3+1}{6} = \frac{4}{6} \approx 0.667\)
  • \(\hat{P}(\text{money}=0 | S) = \frac{1+1}{6} = \frac{2}{6} \approx 0.333\)
  • \(\hat{P}(\text{meeting}=1 | S) = \frac{0+1}{6} = \frac{1}{6} \approx 0.167\)
  • \(\hat{P}(\text{meeting}=0 | S) = \frac{4+1}{6} = \frac{5}{6} \approx 0.833\)

For Ham (\(n_H = 4, V = 2\)):

  • \(\hat{P}(\text{free}=1 | H) = \frac{0+1}{6} = \frac{1}{6} \approx 0.167\)
  • \(\hat{P}(\text{free}=0 | H) = \frac{4+1}{6} = \frac{5}{6} \approx 0.833\)
  • \(\hat{P}(\text{money}=1 | H) = \frac{1+1}{6} = \frac{2}{6} \approx 0.333\)
  • \(\hat{P}(\text{money}=0 | H) = \frac{3+1}{6} = \frac{4}{6} \approx 0.667\)
  • \(\hat{P}(\text{meeting}=1 | H) = \frac{3+1}{6} = \frac{4}{6} \approx 0.667\)
  • \(\hat{P}(\text{meeting}=0 | H) = \frac{1+1}{6} = \frac{2}{6} \approx 0.333\)

Re-classifying \(x^* = (1, 0, 1)\):

\[\text{Score}(S) = 0.5 \times 0.667 \times 0.333 \times 0.167 \approx 0.5 \times 0.0371 \approx 0.0186\] \[\text{Score}(H) = 0.5 \times 0.167 \times 0.667 \times 0.667 \approx 0.5 \times 0.0741 \approx 0.0371\]

Now \(\text{Score}(H) > \text{Score}(S)\), so the email is classified as Ham. The smoothing prevented the zero-probability catastrophe and allowed the model to make a meaningful comparison. Note that without smoothing, the model was completely broken for this input; with smoothing, it correctly identifies that an email with "meeting" present and "money" absent looks more like Ham despite containing "free."

Common mistake

Common mistake: Students often forget to apply Laplace smoothing consistently — smoothing some conditional probabilities but not others, or forgetting to adjust the denominator by \(\alpha V_j\). If you add \(\alpha\) to the numerator but not \(\alpha V_j\) to the denominator, the probabilities no longer sum to 1 across values of \(x_j\), breaking the probabilistic interpretation. Always smooth every conditional probability table uniformly, and always use the corrected denominator. A related mistake: applying smoothing to the prior \(P(y=c)\). Smoothing is needed for conditionals where unseen feature-value/class combinations cause zeros; the prior is estimated from class counts that are rarely zero in reasonable datasets, and smoothing it changes the base rate unjustifiably unless specifically warranted.

Edge case

What happens as \(\alpha \to \infty\)? Every conditional probability \(\hat{P}(x_j = v | y = c) \to \frac{\alpha}{\alpha V_j} = \frac{1}{V_j}\), regardless of the data. All features become uniformly distributed within every class, and the classifier ignores all feature information, predicting purely based on the prior. This is the maximum-bias extreme: complete smoothing erases the signal. Conversely, as \(\alpha \to 0\), we recover the unsmoothed MLE with its zero-frequency vulnerabilities. The optimal \(\alpha\) balances these extremes and should be tuned by cross-validation (Chapter 10), though \(\alpha = 1\) is a widely-used default that works reasonably well in practice.

What if features are continuous? The categorical formulation above doesn't apply directly. Two common solutions: (1) Gaussian Naive Bayes assumes \(x_j | y=c \sim \mathcal{N}(\mu_{jc}, \sigma^2_{jc})\) and estimates \(\mu_{jc}, \sigma^2_{jc}\) per feature per class; the likelihood is then evaluated using the Gaussian PDF. (2) Discretization: bin continuous features into discrete categories and apply the categorical version. Gaussian NB is more common but assumes normality within each class; discretization is nonparametric but loses information at bin boundaries.

Where we go next

Naive Bayes is a generative model: it models how data is produced within each class and uses Bayes' theorem to invert that into a classifier. Logistic regression (Chapter 4) is a discriminative model: it models the decision boundary directly without describing the data-generating process. Both are linear classifiers under appropriate conditions, but they arrive at linearity from fundamentally different starting points. Chapter 7 introduces Linear Discriminant Analysis (LDA), which occupies a middle ground: like Naive Bayes, it is generative and assumes Gaussian class-conditional densities, but unlike Naive Bayes, it allows features to be correlated within classes (shared covariance matrix). LDA provides a principled bridge between the naive independence assumption and fully flexible density estimation.
