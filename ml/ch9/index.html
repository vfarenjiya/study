9. Decision Trees

Chapter 9 of 14 25 min read

Learning by asking questions

Every classifier we have studied so far represents its decision rule as a mathematical function: a linear combination of features (logistic regression, LDA, SVM), a weighted vote of neighbours (kNN), or a product of conditional probabilities (Naive Bayes). These representations are powerful but opaque — explaining why a particular prediction was made requires tracing through coefficients, distances, or probability tables.

The question decision trees answer is: can we build a classifier whose structure directly mirrors human reasoning — a sequence of simple yes/no questions about individual features — while still being learned automatically from data?

The answer is yes, and the resulting model is one of the most interpretable in machine learning. A decision tree partitions feature space into axis-aligned rectangular regions by recursively splitting on single features. Each internal node asks a question ("Is age > 30?"), each branch corresponds to an answer, and each leaf assigns a class label. Prediction for a new point means traversing the tree from root to leaf, answering questions along the way.

Recursive partitioning: the greedy algorithm

Building an optimal decision tree (one that minimizes test error or tree size) is NP-hard. Instead, all practical algorithms use a greedy top-down strategy: at each node, choose the single best split according to some criterion, partition the data, and recurse on each child. No backtracking occurs.

The algorithm skeleton is:

  1. Start with all training data at the root.
  2. If a stopping condition is met (pure node, minimum size, maximum depth), make this node a leaf labeled with the majority class.
  3. Otherwise, evaluate every candidate split across all features. Select the split that maximizes a chosen split quality measure.
  4. Partition the data according to the selected split. Recurse on each child subset.

The entire art of decision tree learning lies in step 3: how do we quantify which split is "best"? Two measures dominate the literature: Gini impurity (used by CART) and information gain (used by ID3/C4.5).

Gini impurity

Suppose a node contains \(n\) samples, of which \(n_c\) belong to class \(c \in \{1, \ldots, C\}\). The proportion of class \(c\) is \(\hat{p}_c = n_c / n\). The Gini impurity of this node is:

\[G = 1 - \sum_{c=1}^{C} \hat{p}_c^2\]

What does this measure? Imagine drawing two samples independently from the node's distribution. The probability they have the same class is \(\sum_c \hat{p}_c^2\). Gini impurity is the probability they have different classes. A pure node (all one class) has \(G = 0\); maximum impurity occurs when classes are equally represented.

For binary classification with proportions \(p\) and \(1-p\):

\[G = 1 - p^2 - (1-p)^2 = 2p(1-p)\]

This is a concave parabola peaking at \(p = 0.5\) with value \(0.5\) and reaching zero at \(p = 0\) and \(p = 1\).

Information gain (entropy-based)

An alternative measure uses Shannon entropy:

\[H = -\sum_{c=1}^{C} \hat{p}_c \log_2 \hat{p}_c\]

(With the convention \(0 \log 0 = 0\).) Entropy measures the expected number of bits needed to encode the class label of a randomly drawn sample from the node. Pure nodes have \(H = 0\); uniform distributions have maximum entropy \(\log_2 C\).

For a candidate split that partitions the node into left and right children with \(n_L\) and \(n_R\) samples respectively, the information gain is:

\[\text{IG} = H_{\text{parent}} - \left(\frac{n_L}{n} H_L + \frac{n_R}{n} H_R\right)\]

This is the reduction in entropy achieved by the split. Higher IG means the split produces purer children. The analogous quantity for Gini impurity is the Gini gain:

\[\Delta G = G_{\text{parent}} - \left(\frac{n_L}{n} G_L + \frac{n_R}{n} G_R\right)\]

Both measures prefer splits that create homogeneous children. In practice, Gini and entropy produce very similar trees; Gini is slightly faster to compute (no logarithms) and is the default in most implementations.

Worked example

Building a tree on a small dataset

Consider \(n = 8\) samples with two binary features (\(A\) and \(B\)) and binary labels:

Sample \(A\) \(B\) Label
100−
200−
301−
401+
510+
610+
711+
811+

Class distribution at root: 3 negative, 5 positive. \(\hat{p}_+ = 5/8\), \(\hat{p}_- = 3/8\).

Step 1: Compute root Gini impurity.

\[G_{\text{root}} = 1 - \left(\frac{5}{8}\right)^2 - \left(\frac{3}{8}\right)^2 = 1 - \frac{25}{64} - \frac{9}{64} = 1 - \frac{34}{64} = \frac{30}{64} = 0.46875\]

Step 2: Evaluate split on feature \(A\).

\(A = 0\): samples {1, 2, 3, 4} → 3 negative, 1 positive. \(\hat{p}_+ = 1/4\).

\[G_L = 1 - (1/4)^2 - (3/4)^2 = 1 - 1/16 - 9/16 = 6/16 = 0.375\]

\(A = 1\): samples {5, 6, 7, 8} → 0 negative, 4 positive. \(\hat{p}_+ = 1\).

\[G_R = 1 - 1^2 - 0^2 = 0\]

Weighted child impurity:

\[\frac{4}{8}(0.375) + \frac{4}{8}(0) = 0.1875\]

Gini gain for \(A\):

\[\Delta G_A = 0.46875 - 0.1875 = 0.28125\]

Step 3: Evaluate split on feature \(B\).

\(B = 0\): samples {1, 2, 5, 6} → 2 negative, 2 positive. \(\hat{p}_+ = 1/2\).

\[G_L = 1 - (1/2)^2 - (1/2)^2 = 1 - 1/4 - 1/4 = 0.5\]

\(B = 1\): samples {3, 4, 7, 8} → 1 negative, 3 positive. \(\hat{p}_+ = 3/4\).

\[G_R = 1 - (3/4)^2 - (1/4)^2 = 1 - 9/16 - 1/16 = 6/16 = 0.375\]

Weighted child impurity:

\[\frac{4}{8}(0.5) + \frac{4}{8}(0.375) = 0.25 + 0.1875 = 0.4375\]

Gini gain for \(B\):

\[\Delta G_B = 0.46875 - 0.4375 = 0.03125\]

Step 4: Choose the best split.

\(\Delta G_A = 0.28125 > \Delta G_B = 0.03125\). Feature \(A\) is selected as the root split.

Step 5: Recurse on children.

Right child (\(A = 1\)): all 4 samples are positive. Node is pure → leaf labeled "+".

Left child (\(A = 0\)): 3 negative, 1 positive. Not pure. Evaluate remaining feature \(B\):

  • \(B = 0\): samples {1, 2} → 2 negative, 0 positive. Pure (−).
  • \(B = 1\): samples {3, 4} → 1 negative, 1 positive. Impure.

Gini of left child before split: \(G = 1 - (1/4)^2 - (3/4)^2 = 0.375\).

Split on \(B\): weighted impurity = \(\frac{2}{4}(0) + \frac{2}{4}(0.5) = 0.25\). Gain = \(0.375 - 0.25 = 0.125 > 0\). Split is beneficial.

After splitting: \(B=0\) leaf is "−"; \(B=1\) node has 1+, 1−. With no remaining features, this becomes a leaf labeled by majority. Tie → typically resolved by parent majority or random choice. Assuming we break ties toward "+": leaf is "+".

Final tree:

  • Root: Is \(A = 1\)?
  • Yes → "+"
  • No → Is \(B = 1\)?
  • Yes → "+" (tie-broken)
  • No → "−"

This tree correctly classifies 7 of 8 training samples (sample 4 is misclassified due to the tie). The tree has depth 2 and 3 leaves.

Overfitting and pruning

Decision trees grown to purity always achieve zero training error (unless identical features have conflicting labels). But deep trees memorize noise and generalize poorly. This is the classic overfitting problem, and decision trees are especially prone to it because each split can isolate individual outliers.

Two strategies combat overfitting:

Pre-pruning (early stopping): Stop growing when a node has fewer than a minimum number of samples, when the impurity reduction falls below a threshold, or when maximum depth is reached. Simple but myopic — a split that looks unhelpful now might enable highly informative splits deeper in the subtree.

Post-pruning: Grow the full tree, then prune back using a validation set or cost-complexity criterion. Cost-complexity pruning (used by CART) defines:

\[R_\alpha(T) = R(T) + \alpha |T|\]

where \(R(T)\) is the training misclassification rate and \(|T|\) is the number of leaves. The parameter \(\alpha \geq 0\) penalizes complexity. For each \(\alpha\), there is an optimal subtree found by weakest-link pruning. Cross-validation (Chapter 10) selects \(\alpha\). Post-pruning generally outperforms pre-pruning because it considers the global tree structure before simplifying.

Common mistake

Common mistake: Students often evaluate split quality using raw impurity of children rather than the weighted average. An unweighted comparison would favor splits that create one tiny pure child and one large impure child over splits that moderately improve both children. The weighting by child size (\(n_L/n\) and \(n_R/n\)) ensures that improvements on larger subsets count more, reflecting their greater impact on overall classification accuracy. Always use the weighted formula: \(\frac{n_L}{n} G_L + \frac{n_R}{n} G_R\), never \(G_L + G_R\) or \(\max(G_L, G_R)\).

Edge case

What happens when all features are identical across samples? No split can reduce impurity. Every candidate split produces children with the same class distribution as the parent, yielding zero gain. The algorithm terminates immediately with a single leaf labeled by the majority class. This is correct behavior: if features carry no discriminative information, no tree structure can help.

What about continuous features? Binary splits on continuous features take the form "\(x_j \leq t\)" for some threshold \(t\). Candidate thresholds are typically midpoints between consecutive sorted unique values of \(x_j\). Each candidate is evaluated using the same Gini/entropy criterion. This makes tree construction \(O(pn \log n)\) per node (sorting dominates), which is efficient enough for moderate datasets but motivates ensemble methods (random forests, gradient boosting) for large-scale problems.
